# Phase 5 — Exploratory Data Analysis: Findings

Dataset: `ds_20260808_547ecf5a_clean` (Phase 3 output, Phase 4 point-in-time
join). Full population = train + val + test = **96,749 loans**
(train 67,724 / val 14,513 / test 14,512, `2022-08-08` .. `2025-08-08`).
Portfolio-level statistics (distributions, frequencies, band default rates,
the temporal check) run on the full population; IV/WOE, the correlation
matrix and point-biserial correlations run on the **train split only** — see
`src/creditguard/eda/run_eda.py`'s module docstring for why. Every number
below comes from `reports/eda/tables/*.csv`, regenerated by
`python -m creditguard.eda.run_eda --dataset-version ds_20260808_547ecf5a_clean`.

## Findings

1. **Class imbalance is moderate, not extreme.** 10,738 of 96,749 loans
   defaulted within 12 months — a **11.10% default rate** (86,011
   non-default). Skewed enough that accuracy is a misleading metric
   (predicting "no default" for everyone already scores 88.9%), but not so
   thin that aggressive resampling is obviously required.

2. **Six numeric features need a log transform before modelling.**
   `numeric_summary`'s `log_transform_flag` (|skewness| > 1.0) is `True` for
   `annual_income` (skew 1.34), `monthly_income` (1.33), `loan_amount`
   (2.89), `interest_rate` (1.01), `loan_tenure_months` (2.11) and
   `post_loan_dti` (1.56). `age`, `dti`, `credit_utilization`,
   `savings_to_income` and `credit_history_years` are all within ±1 skew and
   don't need one.

3. **`loan_to_income` is the single strongest feature in the dataset**
   (IV = 0.660, "suspiciously strong"; point-biserial r = 0.326, the highest
   of any numeric feature) — but this is expected, not a bug:
   `docs/feature_dictionary.md` documents `loan_to_income` as directly used
   in the synthetic label's construction (`+ (via loan_to_income in the
   label)`). Its IV being this high confirms the label design worked as
   documented, not a leakage path to hunt down.

4. **`loan_type`'s IV (0.601, "suspiciously strong") is *not* documented as
   label-construction input and deserves a real look.** `docs/
   feature_dictionary.md` lists `loan_type`'s direction as "mixed/context,"
   not a direct label input. The default rate by loan type shows why IV is
   this high: **HOME loans default at 32.0%** (4,644 of 14,494) versus
   5.5%–11.3% for every other type (AUTO 8.1%, BUSINESS 10.9%, CREDIT_CARD
   5.5%, EDUCATION 7.0%, PERSONAL 6.8%). A ~3–6x default-rate multiplier for
   one category, with no documented mechanism producing it, is exactly the
   pattern the >0.5 IV band exists to flag — worth checking
   `docs/data_generation.md`'s generator logic for an undocumented
   `loan_type`-conditioned effect before Phase 6 trusts this feature at face
   value.

5. **A real IV-computation bug was caught and fixed during this phase, not
   after.** The first `iv_table` run reported `previous_defaults` — the
   bureau field `docs/feature_dictionary.md` calls "the strongest single
   bureau risk signal" — at **IV = 0.0 ("useless")**. Cause: quantile-decile
   binning on a zero-inflated count column (64% of customers have
   `previous_defaults == 0`) collapses every decile cut point onto the same
   value, and `duplicates="drop"` merges them into one bin spanning the
   whole population. Binning by exact value instead gives **IV = 0.106
   ("medium")** with a clean, monotone default-rate gradient: 10.3% at 0
   priors, rising to 14.7% / 22.3% / 27.8% / 36.0% / 53.7% ... up to 100% at
   8+ priors (n≤6 in the highest bins). Fixed in
   `creditguard.eda.risk_analysis.iv_table` (columns with ≤40 distinct
   values now route through exact-value WOE/IV, not quantile deciles); see
   the module docstring for the full before/after. `reports/eda/tables/
   iv_table.csv` already reflects the fix.

6. **19 numeric feature pairs exceed |r| = 0.8 on the train split** —
   material multicollinearity risk for logistic regression. The most severe:
   `credit_history_months` vs. `credit_history_years` (r = 1.000 — literally
   the same field in two units), `existing_loan_amount` vs. `monthly_emi`
   (r = 0.996), `annual_income` vs. `monthly_income` (r = 0.995 — same field,
   two units again), `total_liabilities` vs. `total_outstanding` (r = 0.992).
   A further 15 pairs sit between 0.80 and 0.93 (`annual_income`/
   `monthly_expenses` 0.933, `age`/`credit_history_years` 0.919,
   `previous_defaults`/`has_prior_default` 0.840, `loan_tenure_months`/
   `loan_to_income` 0.823, among others).

7. **Credit utilization shows the textbook risk curve.** Default rate rises
   monotonically by `utilization_band`: 7.5% (0–30% utilized, n=43,525) →
   11.7% (30–50%) → 17.7% (50–70%) → 25.7% (70–90%) → 35.6% (90%+, n=87).
   IV = 0.190 for the raw ratio, 0.163 for the band — "medium" either way,
   and directionally exactly what `docs/feature_dictionary.md` predicts.

8. **Age carries more signal than its documented direction suggests.**
   `docs/feature_dictionary.md` calls age's effect "weak (via
   employment_years/history)," but the observed decile default rate falls
   from 21.3% (youngest decile, 18–27) to 3.1% (oldest decile, 54–100) — a
   ~7x spread — for **IV = 0.348 ("strong")**, the 9th-highest feature in
   the whole set. `age_band` confirms the same monotone pattern (Q1 19.2% →
   Q5 4.1%). Worth reconciling with the label-design docs before treating
   age as a minor feature in Phase 6.

9. **Demographic fields carry essentially no signal, as designed.**
   `gender` (IV = 0.0004), `marital_status` (0.0001), `loan_purpose`
   (0.0006), `education` (0.015), `city_tier` (0.009) and `dependents`
   (0.004) are all in the "useless" band. This matches
   `docs/feature_dictionary.md`'s "not used in the label design" (gender) /
   "mixed/context" characterizations, and is a reassuring signal for later
   fairness/explainability work (Phase 7) — no unintended demographic proxy
   is doing the model's work.

10. **`employment_type == UNEMPLOYED` is a small but sharply higher-risk
    segment.** 715 of 3,231 unemployed applicants defaulted (22.1%) versus
    9.6%–11.3% for salaried/self-employed/business-owner. `employment_type`'s
    overall IV (0.031) is still "weak" because UNEMPLOYED is only 3.3% of
    the portfolio — the signal is real but thin.

11. **No material regime shift across the 3-year window the Phase 4 temporal
    split draws from.** Monthly default rate (`temporal_monthly.csv`,
    Aug 2022 – Aug 2025) stays within roughly 9.6%–12.5% around a mean of
    11.12% (std 0.76 pp), with no visible secular trend. The automated
    z-score check (`detect_regime_shift`, threshold 2σ) flags exactly one
    month, 2024-09 (9.58%), which sits right at the Phase 4 train/val
    boundary (train ends 2024-09-14) — but at ~2,600 loans/month this is
    consistent with ordinary sampling noise, not a sustained level change.
    The temporal split is not artificially cutting across a real regime
    shift.

12. **`loan_tenure_months` combines three separate concerns.** It's the
    2nd-highest feature by both IV (0.487) and point-biserial correlation
    (r = 0.260); it's flagged for a log transform (skew 2.11); and it's one
    of the higher multicollinearity pairs (r = 0.823 with `loan_to_income`).
    All three properties apply to the same feature simultaneously, so it
    needs deliberate handling (transform + regularization), not a
    one-size-fits-once decision.

## Decisions for Phase 6

- **Class imbalance: use class weighting, not synthetic resampling.** At an
  11.10% minority rate this is moderate, not extreme, imbalance — `sample_weight`
  / `class_weight="balanced"` (logistic regression, XGBoost's
  `scale_pos_weight`) is proportionate and keeps every real example in
  training, unlike SMOTE-style oversampling. Per `CLAUDE.md` hard rule #7,
  model selection must use PR-AUC (with ROC-AUC/KS/calibration), never
  accuracy — finding 1 is exactly why.

- **Log-transform before scaling:** `annual_income`, `monthly_income`,
  `loan_amount`, `interest_rate`, `loan_tenure_months`, `post_loan_dti`
  (finding 2; `loan_tenure_months` also needs this per finding 12). All six
  are strictly positive (ratios are already capped by `safe_divide`), so
  `log1p` is a safe default.

- **Multicollinearity for logistic regression (finding 6):** drop one side
  of each near-duplicate pair rather than feeding both — `credit_history_months`
  (keep `credit_history_years`, more directly interpretable), `monthly_income`
  (keep `annual_income`, the documented primary income field), and
  `existing_loan_amount` (keep `monthly_emi`, the direct EMI-burden
  behavioural feature). For the remaining 0.80–0.93 pairs, prefer L2/elastic-net
  regularization over more manual dropping — hand-pruning 19 pairs risks
  discarding real signal, and XGBoost's tree splits are far less sensitive
  to this than logistic regression is, so this decision matters most for
  whichever logistic baseline Phase 6 trains.

- **Leakage re-check before trusting IV at face value:** `loan_to_income`
  (finding 3) is expected — it's documented as a direct label-construction
  input, so its 0.660 IV is confirmation, not a red flag. `loan_type`
  (finding 4, 0.601 IV, HOME loans at 32% vs. 5.5–11.3% elsewhere) is *not*
  documented as a label input and should be traced through
  `docs/data_generation.md`'s generator before Phase 6 uses it unmodified —
  either the documentation is incomplete, or there's a generator-side
  correlation worth understanding (and possibly re-injecting into
  `docs/feature_dictionary.md`'s direction column) before it drives model
  weights.

- **`previous_defaults` (and any other low-cardinality count feature) is
  legitimately useful — don't drop it on a naive IV read.** Finding 5's bug
  is already fixed in `creditguard.eda.risk_analysis.iv_table`, and
  `reports/eda/tables/iv_table.csv` reflects the corrected value
  (IV = 0.106, "medium"). Any ad hoc IV recomputation in Phase 6 should
  reuse this function rather than re-deriving quantile-decile IV by hand,
  or it will silently reproduce the same bug for `previous_defaults`,
  `dependents`, `city_tier`, `num_credit_accounts`, `closed_loans`, and
  every other ≤40-distinct-value numeric feature.

- **Temporal split: no change needed.** Finding 11 found no sustained regime
  shift large enough to invalidate the Phase 4 70/15/15 temporal boundaries
  — the one flagged month is ordinary sampling noise at this volume, not a
  structural break. Proceed with the existing train/val/test split as-is.

- **No new features proposed for Phase 4 rework.** Everything explored here
  (age/utilization/tenure risk curves, the demographic non-signal, the
  employment-type segment effect) is explainable with the existing 77
  engineered features; nothing in this EDA surfaced a missing feature worth
  a deliberate Phase 4 addition.
